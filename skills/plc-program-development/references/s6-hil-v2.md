## 0. 摘要（一页结论）

现在的 S6 并不是"程序测不过"，而是**测量链太粗 + 台架镜像没绑定**，导致大量用例只能判 UNVERIFIED：

| 现象 | 实测（2026-10-23 只读） | 后果 |
|---|---|---|
| 36 点快照跨度 | 436–450 ms（9 个字块 + 5 个线圈块，共 14 个事务） | 10 ms 扫描、100 ms 抖动不可见 |
| 单字读取 | 中位 29 ms | 事件区间宽度 ≈170 ms，与 200 ms 容差重叠 |
| 100 字块读 | 中位 236 ms | 块读受 9600 波特率限制 |
| 当前镜像身份 | D196=4、D202=1、指纹 29415/10550、心跳不递增 | 与 V002 绑定（2/2、28642/27104、心跳递增）不符，门禁必然拒绝 |

**核心方法只有一条**（与链接里的结论一致）：不改接线，用程序预留的 **M/D 软元件模拟输入，再读输出软元件**与 S1 预期比对。V002 程序已经把输入映射层做进梯形图，可以直接用（见 §2）。

下面三件是让这条方法真正可判定的**配套**，不是替代方法：

1. **L0 镜像绑定**：批次开始前用只读 5 字 + 心跳确认"测的就是这个版本"，不匹配直接
   TEST_INFRA_ERROR，禁止写入。这一条今天就能做，且是当前"工作不正常"的直接原因。
2. **L1 传输与事务合并**：USB-RS485 延迟定时器 16 ms→1 ms；快照事务数 14→≤5（9600 下单次读
   ≤2 字）；必要时升到 115200 再改块读。不改 PLC 程序即可把热快照压到 70–90 ms、单字 ≤20 ms，
   事件区间压到 60 ms 以内，足以让休眠/唤醒（容差 200 ms）从 UNVERIFIED 变成 PASS/PROGRAM_FAIL。
3. **L3 PLC 侧事件锁存（V003 程序增补）**：观测块 + 边沿锁存扫描号，把"主机轮询"换成
   "PLC 自己记录"，时序类用例才能到扫描级证据；不增补的程序只能保持 UNVERIFIED，不能靠
   加密轮询假装通过。

## 1. 现状诊断：三个层次的问题

### 1.1 台架镜像与版本绑定（最优先）

V002 证据绑定的身份是 `D196=2, D197=31, D200=28642, D201=27104, D202=2`，并要求 `D198` 心跳前进。
2026-10-23 21:25 只读实测当前台架：

```
D196=4  D197=31  D198=18143(1 s 不变)  D199=-45(1 s 不变)
D200=29415  D201=10550  D202=1
M8000=1(RUN)  M8035=1  M8036=0  M8037=0
```

即：**当前烧录的不是 V002**，而且这个镜像不维护 V002 的 100 ms 心跳与扫描计数器。
按现有 `candidate_bench()/verify()` 逻辑，S6 会在打开串口后立刻因身份不符拒绝写入——这是
**正确的门禁行为**，但表现就是"跑不起来/工作不正常"。

结论：任何 S6 批次的第一步都必须是镜像核对，且必须把"人工下载确认"与"寄存器身份"两件事
同时对齐；只对哈希不对镜像、或只对镜像不对哈希，都不算绑定。

### 1.2 测量链分辨率（决定能判什么）

实测（COM7，9600/8N1，站号 1，只读）：

| 测量项 | 结果 | 说明 |
|---|---|---|
| 单字 FC03 | 27.95 / 29.03 / 30.19 ms（min/中位/max） | 线路时间约 16 ms，其余是 USB 延迟定时器（默认 16 ms）与协议栈 |
| 100 字块 FC03 | 232.2 / 236.6 / 236.8 ms | 205 字节 ≈ 214 ms，受 9600 波特率限制 |
| 36 点快照 | 435.96 / 450.05 / 440.85 ms | 14 个事务逐个叠加，**不是波特率问题** |
| D8120 | 3713 = 0x0E81 | 9600/8/N/1/RTU，与 machine-profile 一致 |

现有判定把"触发区间"定义为 `[写请求, 生效读回结束]`，把"事件区间"定义为
`[最后一次旧值读请求, 第一次新值响应]`。在 29–450 ms 的粒度下，休眠实测区间
`[4816.7, 4992.3]`、唤醒 `[2788.4, 2961.6]`，宽度约 175 ms，与 `4900..5100`、`2900..3100`
的 200 ms 容差重叠，按规则只能 UNVERIFIED。**这是测量能力不足，不是程序缺陷。**

### 1.3 注入语义（V1.0 已经写对，但要落到检查里）

现场结论与 Gemini 讨论一致，且被 L01S 手册地址表证实：

- **X 端子不可写**：L01S 的 X0–X177 在离散输入区 `0x3400–0x347F`，只读（FC02）。写 X 不是
  "写了被覆盖"，而是协议层就不给写。
- **模拟量输入不可写**：D8030–D8033 由 ADC 每扫描刷新；写进去下一扫描就被真实采样覆盖。
- **模拟量输出不可写**：D8050/D8051 在本程序里**每个扫描都被 `MOV K0` / `MOV D132` 重写**，
  主机写入立即被覆盖。
- **正确的注入点**：程序里预留的"输入映射层"——`D190`（测试/硬件模式）、`D1056`（模拟 AI0）、
  `D191/D192`（启停请求）、`D193`（输出使能）、`D102`（在线设定值）、`D261`（保存设定值）。
  这些寄存器程序只读、只在首次扫描初始化，主机写入能保持。

因此 S6 的写入白名单必须是"**程序只读的注入寄存器**"，而不是"任意 D"。写被程序每扫描重写的
寄存器，回读可能瞬时正确，但下一个扫描就被覆盖——这正是"看起来写了、实际没生效"的典型坑。

## 2. 核心方法：软元件注入 → 读输出

S6 只有一条主线，和链接里的结论一致：**不改硬件接线，用程序预留的 M/D 软元件模拟输入，再读输出软元件与 S1 预期比对。** 这也正是 GX Works2 "软元件测试"在做的事，只是换成脚本、可批量、可复现。

V002 程序已经把"输入映射层"做进梯形图，可以直接用：

| 模拟对象 | 注入软元件 | 程序行为 | 可读的派生输出 |
|---|---|---|---|
| 测试/硬件模式 | D190（1=测试输入，0=硬件 AI0） | 每扫描选择 D1056 或 D8030 | D110、D100 |
| 压力传感器 AI0 | D1056（0..4000，带符号） | 钳位后 `(x+12)/25` | D100（0.1 bar） |
| 启动按钮 | D191=1 | 模式有效时置位 M0 | M0、D154、Y0、D8050 |
| 停止按钮 | D192=1 | 复位 M0（停止优先） | M0、D154、D8050 |
| 输出使能 | D193=1 | 允许 Y0/AO 路由 | Y0、D8050 |
| 在线设定值 | D102（10..160） | 钳位并重算阈值 | D260、D262 |
| 保存设定值 | D261 | 仅首次扫描校验 | 重启后的 D102 |
| 写入回声 | D194 | 每扫描复制到 D195 | D195（证明扫描消费了写入） |

最小闭环（对应 STD-011，可直接手测或脚本化）：

```
写 D190=1、D102=60、D1056=1250   → 写 D192=0、D193=1、D191=1
读 M0=1、D154=2000、Y0=1、D8050=1600
写 D192=1                        → 读 M0=0、D154=0、D8050=0、Y0=0
```

这套方法要真的能判 PASS，还差三件配套（不是另一种方法）：

1. **写对软元件**：只写程序"只读"的那些。写 D120/D154/D8050/M0 这类每扫描被梯形图重写的量，
   就是链接里说的"被 MOV 覆盖"——回读可能瞬时正确，下一扫描就没了。
2. **证明写生效**：写完读 `D195` 回声和 `D100` 派生值；只回读写入地址本身不算生效证明。
3. **读输出要有分辨率**：稳态量（M0/M10/M11/D100/D102/D120/D154/D8050/Y0）轮询足够；
   5 s/3 s 定时、100 ms 抖动、单扫描脉冲不是"读一下"能解决的，需要 PLC 侧锁存或外部仪器，
   否则只能 UNVERIFIED。

## 3. 设计不变量（任何版本都不许破）

1. **预期不迁移**：S1 冻结的期望值、容差、时间窗、不变量不得因采集能力不足而修改。
2. **四态不混用**：`PASS` / `PROGRAM_FAIL` / `TEST_INFRA_ERROR` / `UNVERIFIED`。通信失败、
   身份不符、注入未生效属基础设施错误；证据不足属 UNVERIFIED；只有实测偏离预期才是 PROGRAM_FAIL。
3. **区间保守**：测量不确定度并入区间，不并入容差；区间整体落入容差才 PASS，严格不相交才
   PROGRAM_FAIL，其余 UNVERIFIED。
4. **写入最小化**：只写白名单；写前身份校验，写后派生量确认；批次结束恢复安全态并回读确认。
5. **证据可复算**：原始事务（请求/响应字节、时间戳）、镜像身份、源/测试/执行器哈希、批次号
   全部留存；摘要报告不能替代原始轨迹。
6. **独立复核**：S6 判定由 4 个独立上下文 Agent 复核，主 Agent 不计入，不代写结论。

## 4. 分层方案

### L0 台架绑定与身份门禁

| 检查 | 规则 |
|---|---|
| 人工下载确认 | `manual_download.json` 必须绑定当前 source/test 的 SHA256、操作者、时间 |
| 寄存器身份 | 只读 `D196,D197,D200,D201,D202`，与候选 `build_identity.json` 完全一致 |
| 心跳 | `D198` 在 ≥0.25 s 内必须前进；不前进说明程序未运行或不是该镜像 |
| 扫描计数 | `D199` 递增用于换算扫描周期；不维护该计数器的镜像不得进入时序类判定 |
| 失败处理 | 任一项不符 → `TEST_INFRA_ERROR`，关闭串口，**不写任何寄存器** |

补充：身份字只是"辅助核对"，不能替代二进制回读与人工下载记录；两者都要。

### L1 传输与事务合并

目标：把"一次快照"从事务数量上压下来，而不是只提高波特率。

1. **USB-RS485 延迟定时器**：设备管理器 → 端口 → 高级 → Latency Timer 设为 1 ms。
   实测 16 ms 默认值让每个事务多付 16 ms；这是单字 29 ms 的主因。
2. **事务合并按波特率分档**（9600 下"大块读"反而更慢，别盲目合并）：
   - **9600**：单次读 ≤2 个字，热观测点压到 ≤5 个事务。本案例热观测点
     `M0/M10/M11/Y0 + D120/D154 + D8050/D8051` 用"3 次单字 + 2 个线圈组"（共 5 个事务）
     ≈70–75 ms；若改成 `D120..D154` 35 字块读（≈86 ms）再加两个线圈组，反而 ≈110 ms。
   - **115200**：线路时间降到 1/12，改为连续块读，事务数 ≤3（35 字块 ≈5 ms）。
   - 36 点全量快照只在检查点做，不进动态轮询（`D100..D262` 共 163 字，9600 下需 2 次块读 ≈350 ms）。
3. **冷观测点分离**：`D8030–D8033 / D8120 / D8121 / D200–D202` 属静态或诊断量，只在检查点读，
   不进动态轮询。
4. **波特率**：L01S 手册 §8.2.3/§8.3 支持 38400/57600/115200。115200 需把 `D8120` 改为
   `0xE0D1`（8/N/1、115200、RTU；按手册位定义计算，**必须在 V003 首次扫描写入并实测确认**）。
   波特率变更属程序侧改动，不能靠主机写 `D8120` 临时改；失败回退路径只有 COM5。
5. **超时/重试**：超时按"帧时间 + 余量"计算，不沿用固定 0.5 s；`retries=0`，通信错误记录
   **缺失值**而不是 0。
6. **量化目标**：
   - **P0（不改程序，9600 + 延迟 1 ms）**：热快照 ≤90 ms、单字 ≤20 ms、事件区间 ≤60 ms；
   - **P1（115200 + 观测块）**：热快照 ≤20 ms、单字 ≤5 ms、事件区间 ≤10 ms。
   - 参照基线：当前 36 点快照 436–450 ms、单字 29 ms、事件区间约 175 ms。

### L2 注入契约

每次批次开始先做三项"注入自检"，全部通过才允许进入用例：

| 自检 | 方法 | 通过条件 |
|---|---|---|
| 写链路 | 写 `D194=<哨兵值>`，读 `D195` | 下一扫描内 `D195` 等于哨兵（程序每扫描复制 D194→D195） |
| 派生链路 | 写 `D190=1`、`D1056=1250`，读 `D100` | `D100=50`（`(1250+12)/25` 的整数除法） |
| 保持性 | 写注入寄存器后隔 2 个扫描再读 | 值未被程序改写；被改写者移出白名单 |

寄存器分类（以 V002 程序为准，V003 沿用同一语义）：

| 类别 | 寄存器 | 主机可写 | 说明 |
|---|---|---|---|
| 注入（程序只读） | D190,D191,D192,D193,D102,D261,D1056,D194 | 是 | D102 会被钳位到 10..160；D261 仅首次扫描校验，需 STOP/RUN 生效 |
| 程序所有 | D100,D110–D117,D120–D126,D130–D133,D154,D195,D198,D199,D200–D202,D260,D262,D8050,D8051,M0,M1,M2,M3,M10,M11,M12,M20,M21,Y0,T0,T1 | 否 | 每扫描重写或派生，只能观察 |
| 硬件所有 | D8030–D8033（AI）、X0–X177 | 否 | ADC 刷新 / FC02 只读 |
| 系统 | M8000,M8002,M8012,M8125,M8196,D8120,D8121 | 否 | 仅程序首次扫描设置 |
| CPU 控制 | M8035,M8036,M8037 | 仅经 COM5 | Modbus 侧 STOP 后不可用 |

### L3 观测分类与 PLC 侧事件锁存

把用例按"需要的观测能力"分四类，执行策略不同，**不允许把 A/B 的通过率冒充 C 类**：

| 类 | 语义 | 观测手段 | 本案例用例（初版，待 S1 复核） |
|---|---|---|---|
| A 稳态标量 | 写入后稳定保持，任意时刻读一次即可 | 主机块读 + 两次相等 | STD-001..010、012..016、019..028、030、035、038、039、043、048、050、052 |
| B 平台/限幅 | 长稳态（数十秒）后才成立 | 主机单点轮询 + 截止线前成对确认 | STD-029（满频平台）、STD-011（状态机终态） |
| C 时序/瞬态 | 5 s/3 s 定时、100 ms 抖动、单扫描脉冲、计数器回绕 | **PLC 边沿锁存扫描号**（V003）或外部仪器 | STD-031..034、036、037、040..042、044..047、049、051、053..055 |
| D 仅本地 | 需要注入 ADC/电气量 | 不进实机 | STD-017、018、023 |

C 类在没有 V003 观测块时一律 UNVERIFIED；有观测块后按"扫描号差 × 实测扫描周期"判定。

**V003 观测块（程序增补，不改控制逻辑）**：

| 地址 | 内容 |
|---|---|
| D900 | 位域：b0 M0、b1 M10、b2 M11、b3 M12、b4 M20、b5 M21、b6 Y0、b7 M8000、b8 M8012 |
| D901–D916 | 镜像 D100,D102,D110,D120,D154,D190,D191,D192,D193,D198,D199,D8050,D8051,D8030,D260,D262 |
| D920–D923 | M0/M10/M11/Y0 上升沿计数 |
| D940–D945 | 边沿锁存：D191 上升扫描号、M10 置位扫描号、M11 置位扫描号、M11 复位扫描号、Y0 上升扫描号、D154 首次到 5000 扫描号 |
| D960–D962 | 注入回声：主机写 D960 序号 → D961 记录消费扫描号 → D962 记录当时值 |
| D970 | 观测块版本/校验 |

实现约束：只用现有支持子集（LD/ANI/OUT/SET/RST/MOV/ADD/CMP），约 20–30 条指令，放在 END 前，
不改变任何既有输出与状态转移。程序哈希会变，因此必须重新走 S1 冻结（预期不变）、S2、S3、
人工下载、S6。

### L4 时序判定

- **触发区间**：`[写请求发出, 写 ACK + 1 个扫描周期]`。写入在下一个扫描边界生效，扫描周期由
  D199 实测（例如 1 秒内 ΔD199）。
- **事件区间**：轮询方式为 `[最后一次旧值响应开始, 第一次新值响应结束]`；观测块方式为
  `[锁存扫描号 × T_scan, (锁存扫描号+1) × T_scan]`。
- **经过时间**：`[事件下界 − 触发上界, 事件上界 − 触发下界]`，与冻结容差比较。
- **不得**把"读回成功"当作"输入已生效"；不得用后到的稳定值替换截止线断言；不得扩 tolerance。

### L5 执行范围与回归

- 区分**演示范围**与**验收范围**：演示只跑"身份/停止态/换算/设定值/启停/非法模式/一次满频/
  输出使能/一次休眠唤醒/归零"约 10 组；验收按冻结矩阵跑全部适用硬件用例。
- **重启最小化**：只在需要"首次扫描/保存参数"语义时做真实 STOP/RUN（本案例 10 项初始化 + 少量
  首扫描用例），其余用例用注入寄存器复位，避免 27 次重启。
- **分组执行**：按观测类与前置状态分组，单组失败不拖垮全批；仍保留最终清理。
- **回归规则**：仅采集策略变化 → 只重跑受影响的时序/平台程序 + 清理检查；程序或映射变化 →
  全量重评。

### L6 证据与复核

报告头部固定：`program_version / source_sha256 / test_sha256 / plan_sha256 / runner_sha256 /
device_identity(D196,D197,D200,D201,D202) / D8120 / scan_period_ms / test_batch_id / operator /
downloaded_at`。

每个用例记录：类别、观测手段、原始事务序号区间、触发/事件区间、判定、理由、缺失能力。
四态汇总后由 4 个独立 Agent 复核（原始轨迹复算、身份、注入时序、清理），主 Agent 只组织修复。

### L7 安全与资源

- 仅隔离空机台架；不接负载；急停/安全回路不得由 Modbus 绕过。
- COM7 只做数据面；STOP/RUN 只走 COM5（L01S 实测：STOP 后 M8125/M8196 归零，COM7 失效）。
- 单任务独占串口，锁文件带 token；超时/异常路径 try/finally 恢复 RUN、应用停止、输出清零并回读。
- 不全局杀进程、不关闭用户应用、不覆盖既有证据目录。

## 6. 落地阶段与验收指标

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0 立即（不改程序）** | L0 身份门禁 + USB 延迟 1 ms + 事务压到 ≤5（9600 下单次读 ≤2 字）+ 注入三项自检 | 热快照 ≤90 ms；单字 ≤20 ms；事件区间 ≤60 ms；4 项时序相关补充程序重新判定（PASS/FAIL/UNVERIFIED 均可，但必须由证据决定） |
| **P1 传输升级（V003）** | D8120=0xE0D1 + 115200 + 观测块 + 边沿锁存 | 热快照 ≤20 ms；单字 ≤5 ms；事件区间 ≤10 ms；C 类时序可判；注入回声证明"写入被该扫描消费" |
| **P2 全量（V003 之后）** | 55 项按 A/B/C/D 分类执行；C 类全部走锁存 | A/B 类实机判定；C 类有扫描级证据；D 类明确本地；不再出现"55 项全是 capability-only" |

P0 预期效果（不承诺）：休眠/唤醒等 4 项时序相关补充程序当前区间宽度约 175 ms，压到 60 ms 以内后，真实值
（约 5000 ms / 2950–3000 ms）大概率落入 4900–5100 / 2900–3100，从而得到 PASS；若仍贴边，
保持 UNVERIFIED 并记录缺口，不调容差。

## 7. 风险与明确不做的事

- 不把 115200 当默认值直接上线：先 V003 写入、上电复位后实测，失败回退 9600（COM5 恢复）。
- 不用"多次轮询碰巧读到"替代扫描级证据；不给 C 类用例降低要求。
- 不在未确认镜像时写入；不写 X / D8030 / D8050 / 系统继电器。
- 不把寄存器台架结果升级为电气、带载、掉电保持或安全回路验证。
- 不在 P0 阶段改程序哈希；V003 观测块必须重新走 S1/S2/S3/下载/S6 全链。

## 附录 A：事务预算（9600 / 115200）

9600/8N1 每字节约 1.04 ms，115200 每字节约 0.087 ms；实测值含 USB 转换器 16 ms 延迟。

| 事务 | 线路字节 | 9600 线路时间 | 实测（16 ms 延迟） | 115200 估算（1 ms 延迟） |
|---|---|---|---|---|
| 单字 FC03 | 8 + 7 | 15.6 ms | 29 ms | 2–4 ms |
| 2 字 FC03 | 8 + 9 | 17.7 ms | ~30 ms | 2–4 ms |
| 12 位线圈 FC01 | 8 + 7 | 15.6 ms | ~29 ms | 2–4 ms |
| 35 字块 FC03 | 8 + 75 | 86 ms | ~100 ms | 7–9 ms |
| 100 字块 FC03 | 8 + 205 | 222 ms | 236 ms | 20–25 ms |
| 36 点全量快照（14 事务，未合并） | — | — | 436–450 ms | — |
| 热快照（5 事务：3 单字 + 2 线圈组，9600 推荐） | — | ~70 ms | ~75 ms | ~12 ms |

结论：**9600 下不要做大块读**（35 字块 86 ms > 2 次单字 32 ms）；115200 下才改为块读以减少事务。
