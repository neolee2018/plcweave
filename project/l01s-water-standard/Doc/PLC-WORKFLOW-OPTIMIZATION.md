## 问题与归因

1. **最初流程漏项造成返工。** V001未先完成独立S1，用户要求标准重做后重新组织S1/S2/S3；这部分可通过入口门禁避免。
2. **演示任务同时承担工具开发。** 本次新增合格采样判定、V002 CPU身份门禁、PlatformIO台架目标和报告工具。可复用成果有价值，但首次工具开发应单独预算，不能混入成熟案例的交付时限。
3. **硬件可验证性确认偏晚。** 普通9600串口无法证明10ms扫描轨迹，部分事件区间跨越容差边界。应在需求冻结时明确本地全轨迹、硬件稳态、硬件精确时序和电气验证的不同能力。
4. **采集器小改动触发全量实机重跑。** 第二轮只改积分截止采集，但28项全部重跑。更合适的是重跑受影响的饱和程序、必要的输出平台依赖和退出清理，约1分钟级；本次全轮约5分钟，多用约4分钟且未增加其余项目的覆盖。
5. **证据不足的停止规则应更早确定。** 休眠/唤醒实际状态变化已观察，但计时区间不能判通过或失败。精度不足时应保留UNVERIFIED并指出所需测量能力，不靠重复轮询或放宽容差追求PASS。
6. **环境问题重复出现。** PlatformIO安装缓存未刷新、项目模块路径未设置，均在设备动作之外失败。应由一个固定入口预检和统一设置环境。
7. **文档投入与演示阶段不匹配。** 候选阶段先完成37页PDF，最终又形成50页并验收。正式交付资料有必要，但可推迟排版，复用已验收模板，减少未定结果前的完整排版工作。

不把27次真实CPU重启列为首要优化对象：它们有隔离测试状态的作用，本次未证明它们是主要时间瓶颈。为了省少量时间新增复杂软复位框架，反而可能引入状态污染。

## 建议流程

保持S0–S7的责任划分，增加执行范围选择；不每次另建一套流程。

| 环节 | 新规则 | 保留的底线 |
| --- | --- | --- |
| 入口/S0 | 明确演示或验收、时间预算；只读核验型号、版本、映射及采样耗时；识别工具能力缺口 | 未知映射不写设备，现场授权有效 |
| S1 | 独立冻结需求、测试；每项声明验证层级、所需采样能力、前置状态和依赖 | 测试先于程序，S2不能改预期 |
| S2/S3 | 所有适用本地行为测试和快速工具回归照常执行；工具版本可复用已验证结果 | 真指令执行，未知指令阻断，完整轨迹判定 |
| S4 | 建议内部候选先提供CSV、冻结用例、机器报告和版本哈希，最终结果确定后生成正式PDF | 这是对现行完整候选包要求的修订建议，尚未改动技能 |
| S5/S6 | 按需求及能力选择硬件程序；采样精度不足直接记录证据缺口 | 不把稳态采样称完整硬件验收，不扩容差 |
| S7 | 一次生成正式四件套及简明结果摘要；复用模板；内容变更只复检受影响页面 | 原始证据、版本绑定、资源清理与交付哈希 |

## 执行范围与回归规则

**演示范围**：本地55项保留；实机选择约8–10组关键场景，覆盖身份与停止状态、压力换算、设定值、启停优先级、非法模式抑制、一次满频/限幅、输出使能、一次休眠唤醒及最终归零。多组边界放在本地测试，保留少量实际硬件边界点。精确时序仍需具备相应证据能力。

**工程验收范围**：按冻结验收矩阵执行完整适用硬件用例，明确电气/带载/掉电/时序测量条件；演示结果不自动升级为验收。

**工具验证范围**：首次新增或修改驱动、比较器、CPU控制等工具时，独立进行拒绝错误身份、异常通信、截止和清理测试；以版本/哈希保存资格。后续同版本案例复用资格，仍检查连接身份和现场状态。

| 变化 | 最小必要回归 |
| --- | --- |
| PLC程序、硬件映射、驱动或共用判定语义变化 | 全部适用本地回归，重新评估完整硬件范围 |
| 仅单个采集策略变化 | 采集器软件回归、受影响实机程序、必要前置依赖及清理检查 |
| 报告文字或排版变化 | 内容一致性、PDF哈希及受影响页面检查，无需操作PLC |
| 无变化、仅缺乏更高精度证据 | 不重复全量测试；保留UNVERIFIED，列出缺失的测量手段 |

每次执行保存source/suite/backend/plan哈希及所选用例，禁止覆盖旧结果。旧通过证据能否复用由变化影响决定；不能只凭PLC源码未变就认定所有后端修改均无影响。

## 优先实施的四项小改动

1. **固定预检入口**：统一模块路径、UTF8、PlatformIO核心目录和临时目录；比较已安装平台与工作区适配器哈希，不一致时明确刷新；一次输出简短能力报告。
2. **按组/按用例执行**：增加显式选择与依赖检查，保持真实复位和最终清理。先用现有28项分组，不新增调度服务或通用编排平台。
3. **证据不足即停止规则**：采样能力与所需容差不匹配时不进入无效重试；允许一次有明确证据增益的采集改进，仍不足则报告缺口。
4. **文档延后与模板复用**：正式PDF最后生成，首页用验证维度矩阵呈现结果；完整用例作为附录。复核按内容和页面哈希复用，不重新审查所有未变材料。

暂不增加Web前端、后台服务、复杂软复位框架或新的自动下载器。

## 时间目标与验收

对工具已具备、PLC已连接且已烧录的同类案例，目标把续跑从本次约40分钟缩到15–20分钟；这只是待下一案例验证的目标，不是已测得的性能。首次开发新硬件后端另列预算。

下一次试跑记录预检、测试设计、工具开发、PLC测试、独立复核、文档、人工等待各自起止时间。优化验收要求：同样保留独立冻结/错误身份阻断/有效输入回读/真实状态清理；没有未经说明的覆盖下降；单项采集修改不再自动触发全量PLC重跑；交付仍明确区分本地通过、硬件观测、精度不足及未做的电气测试。

本次只形成优化建议，未改现有技能、冻结要求、程序或硬件状态。
