## 2. 核心方法与 P0 四件事

核心方法只有一条：**用程序预留的 M/D 软元件模拟输入，再读输出软元件与 S1 预期比对**（与 GX Works2
"软元件测试"同一原理，改成脚本批量执行）。V002 程序已内置输入映射层，不需要改程序：

| 注入软元件 | 含义 | 读这些输出判断结果 |
|---|---|---|
| D190=1 | 切到测试输入（D1056），0=硬件 AI0 | D110、D100 |
| D1056 | 模拟 AI0 原始值（0..4000，带符号） | D100（`(x+12)/25`） |
| D191=1 / D192=1 | 启动 / 停止请求（停止优先） | M0、D154、Y0、D8050 |
| D193=1 | 输出使能 | Y0、D8050 |
| D102 / D261 | 在线设定值（10..160）/ 保存值（仅首次扫描） | D260、D262、重启后 D102 |
| D194 | 写入回声请求 | D195（证明该扫描消费了写入） |

最小闭环（STD-011）：写 D190=1、D102=60、D1056=1250，写 D192=0、D193=1、D191=1 → 读 M0=1、
D154=2000、Y0=1、D8050=1600；再写 D192=1 → 读 M0=0、D154=0、D8050=0、Y0=0。

要让这条方法真正可判定，P0 做四件配套（都不改程序）：

1. **镜像绑定**：人工烧录 V002 后，先跑只读 preflight（D196/D197/D200/D201/D202 + D198 心跳），
   通过才允许下一批。身份不符 = TEST_INFRA_ERROR，不写任何寄存器。
2. **USB 延迟定时器**：COM7 对应转换器设为 1 ms（设备管理器 → 端口 → 高级）。
3. **事务合并（9600 分档）**：9600 下单次读 ≤2 字，热观测点压到 ≤5 个事务（3 次单字 + 2 个线圈组）；
   不要在 9600 下把 `D120..D154` 做成 35 字块读（86 ms 线路时间，比两次单字还慢）。冷观测点
   （D8030–D8033、D8120/D8121、D200–D202）只在检查点读。
4. **注入三项自检**：D194→D195 回声、D1056=1250→D100=50、注入寄存器 2 个扫描后仍保持。

目标：热快照 ≤90 ms、单字 ≤20 ms、事件区间 ≤60 ms（基线：436–450 ms / 29 ms / 约 175 ms）。

- 四态不变：PASS / PROGRAM_FAIL / TEST_INFRA_ERROR / UNVERIFIED。
- 时序区间按 [S6-HIL-V2 §L4](../../../docs/S6-HIL-V2.md) 计算；区间整体落入容差才 PASS。
- run03 只允许得出两类结论："传输改进后证据充分"或"仍不足，记录缺口"；**不得**为了转 PASS
  调整容差、挑选样本或改预期。
- S6 判定仍由 4 个独立 Agent 复核：①身份与镜像绑定；②原始事务与区间复算；③注入时序与清理；
  ④分类覆盖与报告一致性。主 Agent 不计入。
