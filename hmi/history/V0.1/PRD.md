## 1. 产品目标

在电脑上运行软件，打开一个包含 **X0–X7、Y0–Y7、AD0–AD3、DA1–DA2** 的操作界面。通过 USB-RS485 与真实 PLC 通讯，用开关和数值输入模拟传感器、按钮、限位等输入，观察真实 PLC 执行程序后的输出变化，减少临时接线与手动造信号的时间。

程序运行在真实 L01S CPU 上；电脑负责输入注入与输出观察。首版优先满足工程师逐点手动调试。自动测试、工艺对象闭环模型和其他品牌留给后续版本。

**成立条件：PLC 必须下载与此工具配套的 HIL 程序。** 软件不能让一个仍直接读取 X 或 D8030–D8033 的旧程序自动接受仿真输入。已有程序需要先改造输入映射层，控制逻辑统一使用内部输入镜像。

## 3. 典型使用流程

1. 工程师准备业务程序的 HIL 版和对应接口档案，人工在厂家软件中编译、下载并使 PLC 运行。
2. 双击工具，选择 L01S 档案、COM 口、波特率和站号，点击“连接”。
3. 软件只读核对程序身份、接口版本、PLC 心跳和映射完整性；通过后显示“已连接 · 只读”。
4. 查看仿真输入的待应用值，点击“启用仿真”。软件建立新的仿真会话，确认输入被 PLC 采纳后进入操作态；物理输出联动仍关闭。
5. 点击 X 开关、修改 AD 值，观察 Y 指示灯和 DA 数字。每个输入明确显示“待提交 / 已发送 / 已生效 / 失败”。
6. 需要观察真实输出端子时，在隔离台架上明确启用“物理输出联动”。界面同时显示程序计算值及物理输出寄存器值。
7. 点击“停用仿真”后，先由 PLC 撤销输出联动，再结束会话；确认状态后可断开。若通讯已失效，显示“停用未确认，等待 PLC 超时保护”，不显示成功。

核心闭环：**操作输入 → 注入专用寄存器 → PLC 输入映射 → 原业务逻辑 → 观察输出**。

### 5.2 输入操作细则

- **保持开关**：点击改变目标值并提交；未收到消费确认前，不把目标值当作已生效值。
- **按住有效**：按下提交 1，松开提交 0；失焦、鼠标捕获丢失、停用、断线时均取消按住状态。发送 0 失败时显示未确认，并依靠 PLC 看门狗撤销会话。该操作不承诺精确脉宽。
- **AD 输入框**：只接受档案范围内的整数；默认 0–4000；空白、非数字、负数和越界就地报错，不偷偷截断。回车或“应用”提交，Esc 恢复最近已确认值。
- **AD 滑块**：拖动只更新待应用值，松开提交最后一个值；不按每个像素发送。切换焦点不自动提交输入框中的半成品。
- **应用全部**：将当前 8X+4AD 待应用值组成一组提交；逻辑上保证整组同时生效，不依赖 Modbus 多字写入天然具备扫描原子性。
- **复位仿真输入**：将 X 全部设为 0、AD 设为项目档案中的复位值并提交。该动作不等于复位业务程序，不保证逻辑 Y/DA 归零；若需要关闭实际输出，使用“关闭物理输出联动”。
- **硬件原值**：作为只读辅助信息折叠显示。仿真开启时首页 X/AD 的“已生效值”来自内部镜像，不冒充真实端子状态。

### 5.3 输出与数据质量

仿真关闭物理联动时，Y/DA 的逻辑值仍可变化；物理输出映像应保持门控关闭后的值。联动启用后，显示 PLC 程序实际路由到 Y 和 D8050/D8051 的值。灯亮或寄存器变化只说明程序/输出映像状态，不证明继电器触点、电压或电流实测正常。

连接后未取到的数据显示“—”；错误或过期数据保留最后一次值并标注“已过期”和时间，不伪装为 0/OFF。不仅依赖颜色区分状态，必须同时有文字或图标。不同读事务所得数据保留各自时间戳，整屏不标作同一扫描快照。输出读到超出档案范围的值时保留实际读数并提示异常，不为了匹配量程而截断显示。

### 5.4 操作状态

| 状态 | 可读 | 可写 | 界面行为 |
| --- | --- | --- | --- |
| 未连接 | 否 | 否 | 可编辑本机连接参数与待应用值，明确“未发送” |
| 连接/校验中 | 仅预检 | 否 | 显示当前步骤，允许取消并释放本任务串口 |
| 已连接·只读 | 是 | 否 | 可核对状态；满足档案、下载记录和台架条件后可启用仿真 |
| 仿真启用中 | 是 | 仅会话初始化 | 默认值/待应用值与会话确认后才开放普通操作 |
| 仿真中·联动关闭 | 是 | 仅注入白名单 | 观察逻辑输出；物理输出由 PLC 门控关闭 |
| 仿真中·联动开启 | 是 | 仅注入白名单 | 醒目标明“物理输出联动”，显示两套输出值 |
| 停用中 | 是 | 仅停用协议 | 禁止普通输入操作，等待联动关闭和会话撤销确认 |
| 故障/断线/身份变化 | 尽力只读 | 禁止普通操作 | 立即取消联动意图；停止发心跳及普通写入；重连只读、重新预检，不自动恢复仿真 |

## 6. 寄存器与程序架构

### 6.1 三层分离

```text
电脑上的 X/AD 操作
        ↓ RS485 / Modbus RTU
专用仿真寄存器（上位机写；PLC校验和读取）
        ↓ PLC同一扫描内的输入映射层
逻辑输入镜像（M/D；由PLC写；原业务逻辑统一读取）
        ↓ 共用业务控制核心
逻辑输出镜像（M/D；由PLC写；软件只读）
        ├─ 软件显示逻辑 Y/DA
        └─ PLC输出门控 → Y0–Y7 / D8050–D8051 → 软件只读显示

硬件 X / D8030–D8033 → 只读诊断；正式版输入映射的数据源
```

HIL 版执行仿真输入映射；正式版执行硬件输入映射。两版由同一控制核心生成，正式版去除注入接口和测试会话。**首版不提供运行中一键从仿真切回真实输入**，避免停用/断线时突然采用外部端子值。退出仿真只结束测试会话；恢复正式工作由用户下载正式版完成。

### 6.2 已有能力与新增内容

| 项目 | 当前仓库事实 | 本产品需要 |
| --- | --- | --- |
| 输入/输出映射 | `src/plcweave/variants.py` 已支持独立输入镜像、每点 D 注入、逻辑输出和双版生成 | 复用映射机制，增加连续手动会话契约 |
| 物理输出 | 现有 HIL 生成逻辑不包含正式版的物理输出路由 | 新增受会话和联动开关共同控制的 HIL 输出路由；保持默认关闭 |
| 硬件采样 | `hil.py` 有 L01S 串口参数校验、身份预检、白名单写入和稳态采样 | 补充桌面交互、X 只读采样、连续会话调度、消费确认与状态展示 |
| 长会话保护 | 现有固定用例执行器不能据此认定具备桌面会话租约 | 新增 PLC 侧看门狗、请求暂存/提交/回声及超时锁定 |

不得把现有水泵案例的 D190、D191、D1056 等地址当成所有程序的通用协议，也不直接扩大 `hil.py` 的案例写白名单。

### 6.3 真实硬件映射

依据本仓 L01S 手册 V26.31，完整表见 [params.md](params.md)：

| 界面对象 | PLC硬件软元件 | 零基协议地址 / 读取方式 | 本工具权限 |
| --- | --- | --- | --- |
| X0–X7 硬件原值 | X0–X7 | 0x3400–0x3407，FC02 | 只读 |
| Y0–Y7 物理输出映像 | Y0–Y7 | 0x3300–0x3307，FC01 | 只读 |
| AD0–AD3 硬件原值 | D8030–D8033 | 十进制 8030–8033，FC03 | 只读 |
| 界面 DA1 物理输出值 | 手册 DA0 / D8050 | 十进制 8050，FC03 | 只读 |
| 界面 DA2 物理输出值 | 手册 DA1 / D8051 | 十进制 8051，FC03 | 只读 |

手册 X 为只读离散输入区；AD 寄存器由硬件采样刷新，不能依赖主机写入保持。Y/DA 即使协议具备写能力，本工具也禁止直接写入，输出由业务程序和门控共同负责。

历史 `reusable/programs/89-l01s-daq-template/Doc/02-RS485-Modbus通讯协议.md` 对 X 的功能码仍有“FC02待核实”旧记载；本设计以厂家手册 §8.1.4 的只读输入分区为依据使用 FC02，首次联调只读核对。失败就报告档案不兼容，不静默尝试写入或自动换地址。

通道命名有一位偏移：**界面的 DA2 不代表手册 DA2/D8052**。若用户确实要手册 DA1/DA2 两个通道，需改成 D8051/D8052 并重新确认硬件是否有第三路；不能自动采用这个解释。

### 6.4 仿真接口契约（新增设计，地址尚未分配）

| 逻辑字段 | 方向 | 最低职责 |
| --- | --- | --- |
| 接口版本、构建标识、映射摘要 | PLC → PC | 核对下载程序、项目档案和语义是否匹配 |
| PLC存活计数 / 运行状态 | PLC → PC | 证明程序仍在执行；与主机心跳分开 |
| 会话申请 / 会话确认 / 故障状态 | 双向独立寄存器 | 新会话建立、停用、超时后重新授权；每个地址只由一方写 |
| 主机心跳计数 | PC → PLC | 周期变化；PLC只把有效会话内的新变化作为续租，不接受固定值持续有效 |
| X0–X7暂存值 | PC → PLC | 每点独立 D 字，值仅 0/1；避免多个控件同时读改写同一个位图 |
| AD0–AD3暂存值 | PC → PLC | 每点独立 D 字，默认 0–4000；范围由档案约束 |
| 请求序号 / 提交标记 / 内容校验 | PC → PLC | 暂存完整后最后提交；PLC拒绝未提交、跨会话、重复或校验失败的数据组 |
| 已消费序号 / 生效输入镜像 | PLC → PC | 确认业务逻辑读取的是本次输入；不能只回读暂存区或依赖写ACK |
| 逻辑 Y0–Y7 / DA1–DA2 | PLC → PC | 控制核心计算结果，只读 |
| 物理联动请求 / 联动实际状态 | 双向独立寄存器 | 有效会话内显式开启，PLC返回实际门控状态；超时必须撤销 |

工程实现必须明确提交期间的忙状态和序号一致性：主机只有一组在途提交，收到消费确认前不改暂存；PLC先校验再复制整组到生效镜像，超时按序号查询结果，不直接重放。看门狗心跳使用独立的高优先级事务，不能被拖动滑块产生的队列淹没。

以上是待实现的程序通讯接口，**不是 L01S 厂家特殊寄存器**。本稿不猜测空闲 D/M 地址；开发时依据目标程序的资源表和静态冲突检查分配，形成构建绑定的接口档案，未分配/未核实就禁止联机写入。具体协议算法、资源分配和独立测试在审核通过后的设计阶段完成。

## 7. 物理联动、退出与断线

### 7.1 输出门控规则

只有“有效仿真会话 + 主机心跳未超时 + 显式物理联动请求 + 接口无故障”全部成立，PLC 才把逻辑输出路由到 Y0–Y7 和 D8050/D8051；其余情况下，由 HIL 输出层每扫描将这组物理输出设为关闭值（首版档案默认 Y=OFF、DA原始值=0）。业务核心不得直接写硬件 Y/DA，避免越过门控。

联动开关在每次启动、重连、PLC重启、会话失效后都为关闭。界面确认框显示：本次将联动的 Y/DA 点位、当前逻辑值、设备/构建身份及隔离台架条件。启用后可能立即产生当前逻辑输出，不能把确认框当作业务启动或业务复位。

该门控是调试保护功能，不替代现场急停；“原始值0”的实际电压/电流行为需按输出类型实测，不宣称其天然对应所有现场设备的安全态。

### 7.2 看门狗与失效后的行为

- 设计初值：PC 每 500ms 更新一次主机心跳；PLC 连续 3s 未观察到有效变化就锁定会话失效，撤销物理联动。3s 是首轮联调目标，需要验证 9600bps 下最长事务、调度抖动和程序扫描负担。
- 超时由 PLC 本地计时处理，独立于电脑软件、USB转接器和串口是否还能写入。UI不能承诺断线后还能发出“清零”。
- 会话失效后，生效 X 置0、AD采用档案失效值（默认0），逻辑输出允许继续显示业务核心结果；物理输出由门控关闭。
- 恢复通讯不恢复旧会话、不自动切到硬件输入、不重放旧操作。重新预检、新会话确认后才能继续仿真，物理联动仍需重新明确开启。
- 超时后的晚到请求和心跳不得重新激活联动；必须通过新的会话握手。会话号和序号回绕/重启处理属于实现前必测边界。

### 7.3 正常停用和资源释放

停用先请求关闭联动并确认实际门控/物理输出映像，再撤销会话；关闭窗口走相同路径。清理总等待上限建议 5s，失败就保留“未确认”的退出记录并释放本任务串口/锁；PLC 看门狗负责兜底。不会为了等待退出无限占用串口，也不关闭用户其他串口软件或进程。

## 8. 通讯与刷新体验

1. **链路**：Windows → USB-RS485 → L01S串口2；PLC为Modbus RTU从站。首版一次只控制一台PLC，一个串口一个主站；用户其他软件占用时明确提示，不抢占。
2. **参数**：默认建议9600/8N1、站号1；COM由用户选取，不能硬编码COM7。上位机不在线改D8120/D8121/M8196/M8125。
3. **地址**：配置显示PLC软元件、零基协议地址和地址区；报文不叠加40001。读X用FC02、读Y用FC01、读D用FC03；写操作仅限已审核仿真契约的D白名单。实际支持的写功能码需只在专用注入区联调确认。
4. **调度**：串口事务串行；心跳/停用优先于输入提交，提交优先于普通轮询。慢事务有超时，轮询无叠加，断线不积压写入。连接、轮询和超时不能卡住窗口。
5. **刷新**：默认目标刷新周期250ms，可选500/1000ms；根据实际读取耗时显示真实数据年龄，达不到250ms时自动降低频率并提示，不显示虚假的4Hz实时性。
6. **体验指标**：本机操作视觉反馈目标≤100ms；在9600bps、健康链路且无重试时，“提交到已生效确认+首个输出观察”目标P95≤1s；这些是待实测验收指标，非已有性能。
7. **快照边界**：输入消费用PLC确认序号；输出由多次读取组成时，记录每块读取时间和跨块跨度。首版只支持手动稳态观察，不以普通轮询保证短脉冲捕获。

协议地址从零起算与功能码语义参考 [Modbus官方应用协议V1.1b3](https://www.modbus.org/docs/Modbus_Application_Protocol_V1_1b3.pdf)；L01S地址以本地厂家资料为依据，不套用其他FX兼容机型的地址。

## 9. 配置、记录与兼容

### 9.1 配置边界

- **设备档案**：机型、固件适用范围、协议地址规则、通道数量、AD/DA量程与符号类型；首版只提供已核实L01S档案。
- **程序接口档案**：绑定项目、HIL构建身份、各注入/镜像/会话地址、白名单、复位/失效值、输出路由与看门狗契约；不能仅凭“L01S”机型名写寄存器。
- **本机偏好**：窗口大小、COM参数、最近使用档案；启动可恢复选择，但不自动连接或写入。
- 程序接口以项目 `design.md` 资源表为维护源；之后若生成机器可读档案，应是带版本/哈希的构建产物，不维护第二份手工地址真相。
- 默认以原始值调试，工程单位仅在档案提供量程时显示。电压/电流/温度等类型不由通道号推断；未配置时显示“原始值”，不编造V/mA换算。

### 9.2 会话记录

每次会话至少记录：开始/结束时间、会话ID、工具版本、设备与接口档案版本/哈希、程序构建标识、人工下载确认引用、串口参数、请求序号、目标输入、PLC已消费输入、输出逻辑值/物理值、各读写时间、错误与停用确认。记录可导出至用户指定目录；默认建议放在相应客户项目的 `evidence/manual-hil/<会话ID>/`。

记录服务于手工复现与问题定位。首版不自动输出用例PASS，也不把某次手动观察升级为正式HIL验收；后续接入自动比较器时保留原来的冻结预期和证据等级。

### 9.3 多机型扩展

界面、点位交互、会话状态与记录格式共用；设备适配器负责传输、地址规则、通道量程和能力声明。未知固件、缺通道、未实现功能码或不兼容接口版本明确阻断相应操作。新增品牌必须重新核对协议和实测，不能只换名称继承L01S能力结论。
