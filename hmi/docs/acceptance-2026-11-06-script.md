# V0.5 Python 测试脚本与桌面联动验收

日期：2026-11-06。范围：工具层，不修改客户原始程序、测试用例和历史证据。

## 实现与证据

- 优先脚本：`project/l01s-water-standard/run_hil_v3.py`，原文件不变。`script_projects.py` 以实际 `source.fxil` SHA-256 绑定五字身份、AD0 输入路径与客户寄存器默认定义；未指定输出目录时追加唯一 `--output`。
- 原脚本在独立进程执行。观察器保留客户端实例、上下文管理、属性和原返回/异常；记录 pymodbus 与本仓 RTU 的实际请求/响应、原始 serial 字节及 stdout/stderr。写入意图先落盘再调用原方法。
- 脚本期间 GUI 释放自身连接，不竞争串口；仅成功读回更新状态。首次成功事务确定主图端点，失败站号探测不污染目标。其他设备事务仍完整留在日志。
- Windows Job Object 和 START 屏障约束本次进程树；根进程退出后终止未退出后代，等待 Job 活动数归零及已持有后代句柄变为 signaled，再结束 reader/watcher。完成事件只在清理后发出。
- “测试完毕”原生弹窗显示进程退出码和脚本报告；明确确定后才进入新手动记录。脚本报告 `PROGRAM_FAIL` / `TEST_INFRA_ERROR` 等失败状态不会因为进程退出码 0 而记作正常测试结果。没有脚本报告时只陈述进程结束，不推断用例通过。
- 压力工程 AD0 写 D1056、读 D110，前提 D190=1；不满足时拒绝并保留 MANUAL，允许在客户寄存器区改模式后重试。身份变化或通讯失败会阻断写入。D102 为设定压力，D260 默认只读。其余没有定义的输入禁用。
- 关闭时排空已收集事件；清理失败写日志及 `script_cleanup_error` 摘要。脚本原始 JSONL 进入 ZIP，主日志和原始日志分别标截止序号；运行中导出不承诺二者是同一时刻。

## 实际验证

- 最终仓库全量测试：`python -m pytest tests -q -p no:cacheprovider`，**321 passed，83.72s**。
- 中间一轮定向复验发现目标同步后的 X0 切换断言仍按旧初值、失败后的 Tk 多实例 GC 干扰；已按实际新目标验证切换，将 GUI 测试模块的循环收集固定在主线程，并让 fixture 通过完整关闭路径释放资源。最终全量回归覆盖这些修改；不把旧结果替代新失败。
- 原优先脚本通过宿主运行 `--help`，验证导入、参数和输出接入；演示模式禁止物理串口，未执行任何硬件事务。
- 真实演示脚本经子进程、实际 RTU 回环收发、GUI、原生完成弹窗，再由截图脚本确定并执行手动写入/读回。截图包含当前版本水印；见 [主画面说明](screens/main.md)。全部截图生成于任务自建临时配置与日志目录，未改用户配置。
- 默认 1280×800 的 AD 数值、设定框/应用、底部监控表与发送栏真实显示；1024×768 的重点控件有边界检查。125%/150% DPI 下既有顶栏/控件拥挤问题未在本轮改造，仍列于 [backlog](index.md#backlog后续迭代候选)。
